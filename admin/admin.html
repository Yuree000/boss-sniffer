自动打招呼

⚠️ chrome.debugger 模式：启用后会模拟点击 BOSS 页面"打招呼"按钮， 浏览器顶部会持续显示"已开始调试此浏览器"警告条。这是扩展正常工作的副作用， 关闭 sayHi 开关警告条即消失。

"启用自动打招呼" 已搬到侧边栏运行时控制；admin 仅配置节流参数。判定标准：v0.12 二态决策后仅「符合」候选人会被入队。

每次打招呼之间随机等待 [下限, 上限] 毫秒，模拟人类操作
打满 N 人后强制休息 [min, max] 分钟，让账号看起来像真人

评估后自动求简历（v0.17.1.3）

⚠️ 仅批量评估自动 / 单评始终手动：开启后，批量评估时所有判为「符合」的候选人会自动： ① 选中卡片 ② 输入当前话术 ③ 点求简历 ④ 弹窗确定。 单评（点单个候选人 ⚡）永远不会自动求简历——HR 看到结果后自己点 🎯 决定。 默认 OFF；跑通 1 人确认安全后再开。
关闭时批量评估也只评估不操作；HR 看完每张卡片手动点 🎯 决定
开启时执行链路走完所有定位 + log，但**不**点最后的发送 / 确定。BOSS UI 改时调试用
自动求简历专属冷却（默认 2-4s）。链路自身已耗 13-25s/人，叠加大幅冷却会让 HR 觉得卡死。

沟通页 DOM 扫描（v0.17.0.10）

评估"新招呼"候选人时，主扩展会模拟点击每个候选人触发 BOSS 渲染右侧详情面板， 然后扫 DOM 拿期望城市/个人简介/工作经历长文本喂 LLM。 必须串行 + 拟人冷却，避免被 BOSS 行为分析识别。

单批上限：轮 1 测试用 1，跑通后调 5、15；0 = 不限制（不推荐）。
主动 fetch：默认关。DOM 扫描的模拟点击已经会让 BOSS 自调 chat/geek/info（HR 真实行为），开启会双倍流量增加风控嫌疑。
每扫一个候选人后随机等待 [下限, 上限] 毫秒再扫下一个。HR 看简历通常 5-10 秒，默认 5000-8000。

大模型配置教程

        
      

      

        

          
DeepSeek

          
协议选择 OpenAI Compatible，Base URL 填 https://api.deepseek.com，模型可填 deepseek-chat 或 deepseek-reasoner，鉴权方式选 Bearer Token。

        

        

          
通义千问 / DashScope

          
协议选择 OpenAI Compatible，Base URL 通常填兼容模式地址，模型可填 qwen-plus 或 qwen-turbo，鉴权方式选 Bearer Token。

        

        

          
Kimi

          
协议选择 OpenAI Compatible，Base URL 填 Kimi 的 OpenAI 兼容接口地址，模型可填 moonshot-v1-8k，鉴权方式选 Bearer Token。

        

        

          
Claude / Anthropic

          
协议选择 Anthropic Messages，Base URL 填 https://api.anthropic.com，模型填 Claude 模型名，鉴权方式选 x-api-key。

        

        

          
自定义兼容接口

          
OneAPI、OpenRouter 或公司代理如果兼容 OpenAI Chat Completions，协议选 OpenAI Compatible，Base URL 填到服务前缀即可；保存或测试时浏览器会请求该域名访问权限。
